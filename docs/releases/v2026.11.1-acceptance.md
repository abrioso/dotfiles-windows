On a clean test checkout, explicitly fetch and select the release branch, then verify the full SHA
against the one recorded from the PR. Do not overwrite local edits to obtain a clean checkout.

```powershell
git fetch origin
git switch release/v2026.11.1
git merge --ff-only origin/release/v2026.11.1
if ($LASTEXITCODE -ne 0) { throw 'Candidate checkout failed.' }
$ExpectedCommit = Read-Host 'Full candidate head SHA from the release PR'
if ($ExpectedCommit -notmatch '^[0-9a-fA-F]{40}$') { throw 'Invalid candidate SHA.' }
$ActualCommit = git rev-parse HEAD
if ($LASTEXITCODE -ne 0 -or $ActualCommit -ne $ExpectedCommit) { throw 'Candidate SHA mismatch.' }
git status --short --branch
```

## Docker lifecycle and data preservation

These standalone utilities are outside setup. Use a disposable VM and a dedicated Compose directory
and unique project name, such as `dotfiles-release-acceptance`. Keep that same project name on every
invocation. Use only test models/chats and test volumes. Record actual mounted volume names with
`docker inspect`; add recognizable test data and record its content/hash through the application
or a suitable test container before stopping the stack. Never run Purge against an existing stack.

- [ ] Start with an explicit ComposePath; first generation uses the managed marker, localhost ports
      and opt-in Watchtower. Start waits for running/healthy services and reports Docker failures.
- [ ] Re-running start preserves existing Compose content byte-for-byte.
- [ ] Stop (the default) leaves containers/volumes; start again and verify the recorded test data.
- [ ] Down removes containers/networks, retains volumes; start again and verify the same test data.
- [ ] Purge -WhatIf removes nothing. Declining the interactive Purge confirmation removes nothing.
- [ ] In an isolated session with ConfirmPreference None, Purge still prompts unless Confirm is
      explicitly bound. Decline it and verify the volumes/data remain.
- [ ] Only on the disposable project: explicitly confirm Purge and verify its managed test volumes
      are removed. Retain volume inventory and confirmation evidence. External volumes, if used,
      are owned separately and are not expected to be removed by Compose down --volumes.
- [ ] An unrelated/unmarked Compose file is rejected; legacy migration preserves original project
      identity and volume mappings. The retired direct-run helper only emits migration guidance.
- [ ] On a GPU host, Ollama can use the intended GPU and Open WebUI reaches it; otherwise record
      GPU acceptance as unexecuted and resolve the release limitation explicitly.
